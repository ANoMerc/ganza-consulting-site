# Ganza Consulting — сайт

Статический сайт (HTML/CSS/JS, без сборки), готов к деплою на GitHub Pages.

## Структура

```
index.html          — главная, RU (по умолчанию)
en/index.html        — главная, EN (полный дубликат index.html под индексацию на английском)
css/style.css        — основные стили
css/builder.css       — стили конструктора проекта (баннер + модалка)
js/script.js          — переключатель языка и мобильное меню
js/builder.js          — конструктор проекта: движок оценки + UI визарда
img/og-cover.png|jpg  — обложка для соцсетей/мессенджеров (Open Graph)
robots.txt            — разрешает индексацию, ссылается на sitemap
sitemap.xml           — карта сайта с hreflang RU/EN + все статьи блога
css/blog.css          — стили блога (лента карточек + вёрстка статьи)
build_blog.py          — генератор блога: правишь POSTS → запускаешь скрипт → получаешь HTML
blog/index.html         — лента блога (сгенерировано)
blog/<slug>/index.html   — страница отдельной статьи, 8 шт. (сгенерировано)
img/blog/<slug>-cover.png — обложка статьи для соцсетей, 8 шт. (сгенерировано)
```

## SEO и индексация на двух языках

Проблема: RU/EN переключаются на клиенте через `data-lang`, и оба текста физически лежат в одном HTML — если бы страница была одна, Google проиндексировал бы только язык по умолчанию (RU). Решение: `index.html` (RU, `data-lang="ru"`) и `en/index.html` (EN, `data-lang="en"`) — это два физических файла с одинаковой вёрсткой, но разным языком по умолчанию, разными `<title>`/`<meta description>`/OG-тегами и `hreflang`-ссылками друг на друга. JS-переключатель работает на обеих страницах как раньше — мгновенно, без перезагрузки.

**Если меняешь текст сайта** — правь `index.html`, затем перегенерируй `en/index.html` (или попроси меня это сделать) так, чтобы вёрстка не разошлась. Пути к ассетам в `en/index.html` идут с `../` (`../css/style.css` и т.п.), потому что файл лежит в подпапке — это единственное структурное отличие от `index.html`.

**Перед первым деплоем** замени `https://anomerc.github.io/ganza-consulting-site/` в `index.html`, `en/index.html`, `sitemap.xml` и `robots.txt` на реальный адрес сайта, если он изменится (свой домен или другое имя репозитория).

**После деплоя**, чтобы ускорить индексацию: добавь сайт в [Google Search Console](https://search.google.com/search-console) (подтверждение через HTML-тег в `<head>` или DNS-запись — код подтверждения нужно будет добавить в оба файла) и отправь `sitemap.xml` там же.

## Конструктор проекта («Собери свой проект»)

Бесплатная интерактивная игрушка внутри секции «Услуги» — баннер открывает модальное окно с визардом из 6 вопросов и на выходе даёт вилку по срокам (в неделях) и бюджету ($ и ≈₽).

**Как считает** (весь код в `js/builder.js`, комментарий в начале файла):

```
personDays         = масштаб × базовые_дни_на_единицу[тип] × готовность_процессов × координация
personDaysWithRisk  = personDays × (1 + буфер_риска)
эффективность команды = clamp(1 − 0.035 × (команда − 1), 0.60, 1)   ← оверхед координации с ростом команды
календарные_дни      = personDaysWithRisk / (команда × эффективность)
срок (диапазон)       = календарные_дни × [1 − полоса×0.5 , 1 + полоса]
бюджет (среднее)      = personDaysWithRisk × ставка[тип]             ← стоимость зависит от объёма работы, а не от календарного срока
бюджет (диапазон)     = бюджет_среднее × [1 − полоса×0.5 , 1 + полоса]
```

`базовые_дни_на_единицу`, `ставка`, буферы риска и коэффициент координации — константы в объектах `TYPE_CONFIG` / `RISK_CONFIG` в начале `js/builder.js`, откалиброванные по твоим кейсам и тарифам с сайта (ставки: разбор сложных случаев $190/день, автоматизация нетиповых процессов $220/день, управление сложными проектами $180/день, нестандартная веб-разработка $195/день). Захочешь поправить экономику (например, ставку за person-day для автоматизации) — меняешь одно число там, ничего больше трогать не нужно.

Пользователю в UI показывается блок «Как мы это считаем» с разбивкой по каждому выбранному фактору — это осознанно: старый калькулятор из другого проекта врал про «ИИ-коэффициенты −12%» без обоснования, тут — честная и понятная логика.

Кнопка «Обсудить в Telegram» в конце открывает чат с @groovebliss и **автоматически подставляет текст** с итогами (тип проекта, срок, бюджет) — это и есть механика лидогенерации: директор доигрывает до конца и сразу пишет тебе с готовым брифом.

## Деплой на GitHub Pages

1. Создай репозиторий на GitHub (например `ganza-consulting`).
2. Залей туда содержимое этой папки (важно: `index.html` должен лежать в корне репозитория, либо в папке `docs`).
3. В репозитории: **Settings → Pages → Build and deployment → Source: Deploy from a branch**.
4. Выбери branch `main` и папку `/ (root)` (или `/docs`, если положил файлы туда) → **Save**.
5. Через 1–2 минуты сайт появится по адресу `https://<твой-юзернейм>.github.io/ganza-consulting/`.

### Если хочешь свой домен
Добавь файл `CNAME` в корень с одной строкой — твоим доменом (например `ganzaconsulting.com`), и настрой A/CNAME записи у регистратора на GitHub Pages.

## Прайсинг

Тарифы построены не как воронка «аудит → внедрение → сопровождение», а как набор форматов под единичную сложную задачу:

- **Флагман — «Задача, от которой отказались другие»**: индивидуальный расчёт, от $2 500, обычно 2–6 недель.
- **«Точечная экспертиза»**: $450, срок 3–5 дней.
- **«Быстрое внедрение точечного решения»**: от $1 100, 1–3 недели.
- **«Экспертный резерв»**: от $1 400/мес, ежемесячно.

Цены в рублях специально убраны с сайта — только $ (аудитория интернациональная, а курс меняется быстрее, чем сайт обновляется). Под каждым тарифом — блок «Почему такая цена» (компонент `.price-card__why`, тот же брутalist-паттерн `<details>`, что и в конструкторе), где расписаны факторы, из которых складывается цена конкретного тарифа — это осознанно закрывает вопрос «а из чего вообще состоит цифра».

## FAQ / Возражения

Секция `#faq` (после прайсинга) — бруталистский аккордеон на нативных `<details>/<summary>` с 4 самыми частыми возражениями: «дорого — почему не штатный сотрудник», «нет гарантии результата», «маленькая студия / один человек», «конфиденциальность данных». Каждый пункт отвечает прямо, без уклончивых формулировок, и не пытается закрыть возражение, если честный ответ — «мы не гарантируем результат заранее». Добавить/поправить пункт — просто отредактировать соответствующий `<details class="faq-item">` в `index.html`, вёрстка (плюс/минус-иконка, аккордеон) уже готова.

## Блог

Вкладка «Блог» в шапке (`/blog/`) — лента из 8 статей, каждая карточка с SEO-заголовком, тегом, временем чтения и кратким описанием; клик уводит на отдельную страницу `/blog/<slug>/` со своим `<title>`, `meta description`, canonical, OG-обложкой и JSON-LD (`Article`) — то есть каждая статья индексируется отдельно, независимо от главной.

Блог **только на английском** (без RU/EN переключателя — статьи изначально написаны на английском под интернациональную аудиторию), поэтому в шапке блога нет кнопки переключения языка, а верстка страниц переиспользует те же переменные и классы, что и основной сайт (`style.css` + `builder.css` + `blog.css`).

**Как добавить/поправить статью:**

1. Открой `build_blog.py`, найди список `POSTS` в начале файла.
2. Добавь новый словарь (или отредактируй существующий) с полями `slug`, `date`, `tag`, `title`, `dek`, `description`, `body` (список кортежей `("p", "текст абзаца")` / `("ul", ["пункт1", "пункт2"])` / `("q", "текст врезки-цитаты")`) и `hashtags`.
3. Запусти:

```bash
python3 build_blog.py
```

Скрипт перегенерирует `blog/index.html` и все `blog/<slug>/index.html` — время чтения посчитается автоматически по числу слов.

4. Для новой статьи сделай обложку `img/blog/<slug>-cover.png` (1200×630, тот же стиль, что у остальных — тёмный фон, толстая рамка, заголовок шрифтом Archivo Black) — вручную или попроси меня сгенерировать.
5. Добавь новый URL `https://.../blog/<slug>/` в `sitemap.xml` (по образцу уже существующих записей блога).

> Файл `linkedin/ganza-linkedin-articles.md` с теми же текстами в LinkedIn-формате больше не основной канал публикации — он остаётся на диске как черновик для копипаста в LinkedIn, если понадобится, но сайт теперь самостоятельный источник этих статей с собственной SEO-индексацией.

## Переключатель языка

По умолчанию сайт открывается на русском (`<html lang="ru" data-lang="ru">`). Переключение RU/EN — чисто на фронтенде, без сохранения выбора между визитами (специально, чтобы не тянуть куки/localStorage на статическом сайте). При желании легко добавить `localStorage`, чтобы язык запоминался — правь `js/script.js`, функцию `setLang`.

## Локальный просмотр

Просто открой `index.html` в браузере, либо из папки:

```bash
python3 -m http.server 8000
```

и зайди на `http://localhost:8000`.
