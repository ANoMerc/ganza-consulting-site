# Ganza Consulting — сайт

Статический сайт (HTML/CSS/JS, без сборщиков и зависимостей) для GitHub Pages,
с двуязычным блогом и собственной аналитикой на Supabase.

---

## 1. Быстрый старт: три команды

```bash
python3 build_site.py      # главная: / (EN) + /ru/ (RU) + /en/ (редирект)
python3 build_blog.py      # блог: 12 статей × 2 языка + ленты + RSS
python3 build_sitemap.py   # sitemap.xml + robots.txt + .nojekyll
```

Локальный просмотр:

```bash
python3 -m http.server 8000
```

## 2. Структура

```

buildlib.py                общие блоки: <head>, шапка, подвал, JSON-LD, домен
build_site.py              генератор главной
build_blog.py              генератор блога
build_sitemap.py           генератор sitemap/robots

ru/index.html              главная RU  (генерируется)
en/index.html              редирект на / — чтобы старые ссылки не умерли
blog/…                     английский блог (генерируется)
ru/blog/…                  русский блог (генерируется)
```

> Всё, что помечено «генерируется», перезаписывается при сборке. Правки в этих
> файлах будут потеряны — правь исходники и пересобирай.

## 3. Языки и SEO-схема

Раньше: RU в корне, EN в `/en/`, блог только EN. Теперь:

| URL | Язык | Роль |
|---|---|---|
| `/` | EN | главная по умолчанию, `x-default` |
| `/ru/` | RU | русская главная |
| `/en/` | — | редирект на `/` + `noindex`, чтобы не потерять уже проиндексированное |
| `/blog/` `/blog/<slug>/` | EN | английский блог |
| `/ru/blog/` `/ru/blog/<slug>/` | RU | русский блог |

**Кнопка RU/EN работает везде.** На главной оба языка лежат в одном HTML
(`.lang-ru` / `.lang-en`), поэтому переключение мгновенное, без перезагрузки, и
одновременно адрес в строке браузера меняется на `/` или `/ru/` — ссылку можно
скопировать и она откроется на нужном языке. В блоге статьи длинные, поэтому
дублировать оба языка в одной странице было бы вредно для скорости и индексации:
там кнопка — обычная ссылка на зеркальную статью (`/blog/x/` ↔ `/ru/blog/x/`),
связанную через `hreflang`.

Что настроено под поисковики:

- `hreflang` en / ru / x-default взаимно на всех страницах, `canonical` на самого себя;
- JSON-LD: `Organization`, `WebSite`, `Person` (E-E-A-T автора), `ProfessionalService`
  с `OfferCatalog` по тарифам, `FAQPage` (собирается **из реальной разметки** секции
  FAQ, поэтому не может разойтись с текстом), `BlogPosting`, `BreadcrumbList`,
  `ItemList`, плюс `FAQPage` в каждой статье;
- `Open Graph` + `Twitter Card` с обложкой 1200×630 на каждой странице;
- RSS-ленты `/blog/feed.xml` и `/ru/blog/feed.xml`;
- хлебные крошки, оглавление, блок выводов, FAQ, блок автора, перелинковка
  «по теме» — то есть и структура для читателя, и сигналы для AI-выдачи;
- `sitemap.xml` со всеми 26 URL и парами `hreflang`;
- `robots.txt` закрывает `/admin/`, `/_src/`, `/en/`.

**Перед публикацией:** если домен изменится, поменяй одну строку `SITE` в
`buildlib.py` и пересобери — canonical, hreflang, JSON-LD и sitemap обновятся сами.

## 3.5. Оформление: Liquid Glass

Внешний вид задаёт **`css/glass.css`** — отдельный слой поверх `style.css`,
`builder.css` и `blog.css`. Он не трогает разметку и сетки, только материал:
фон, границы, скругления, тени, цвет текста.

- **Откат:** убрать `"glass"` из списка `css=(...)` в `build_site.py` и
  `build_blog.py` и пересобрать — вернётся исходный бруталистский вид.
- **Фон** рисуется одним псевдоэлементом `body::before`: три цветных пятна
  дрейфуют 46 секунд по кругу. Плюс лёгкое зерно в `body::after` — без него
  стекло выглядит пластиковым.
- **Страницы статей** получают класс `page-article`: фон остаётся тёмным, но
  замирает и приглушается, чтобы длинный текст читался. Стекло остаётся в
  шапке, оглавлении, врезках, таблицах и CTA.
- **Палитра не менялась**: жёлтый `#e8ff2e`, синий `#2f2ef0`, красный
  `#e8432c`. Изменилась только основа — с бумажной на чернильную.

**Что заложено сразу (не удалять при правках):**

| Условие | Что происходит |
|---|---|
| `prefers-reduced-motion` | пятна перестают двигаться, ховеры не смещают карточки |
| `prefers-reduced-transparency` | размытие выключается, панели становятся плотными — иначе текст стал бы нечитаемым |
| ширина < 900px | `backdrop-filter` остаётся только в шапке: два десятка размытых слоёв кладут средние телефоны |
| `:focus-visible` | жёлтая обводка на всех интерактивных элементах |

**Обложки статей** генерируются в том же стиле: `python3 make_covers.py`.
Заголовок берётся из `h1` статьи (часть до `:` или `(`), цвет акцента — из тега.
Шрифты лежат в `_src/fonts/` (Archivo Black и Space Mono, лицензия SIL OFL).
Добавил статью — запусти скрипт, обложка появится сама.

## 4. Блог

12 статей, каждая 8–10 минут чтения на обоих языках, с оглавлением, таблицами,
чек-листами, пошаговыми блоками, выводами и FAQ.

**Как добавить статью:**

1. Скопируй любой файл из `content/posts/` под новым именем `<slug>.py`.
2. Заполни поля: `date`, `tag`, `title`, `h1`, `dek`, `description`, `keywords`,
   `hashtags`, `related`, `body`, `takeaways`, `faq` — каждое с ключами `en` и `ru`.
3. Блоки `body`: `("h2", …)`, `("h3", …)`, `("p", …)`, `("ul", [...])`, `("ol", [...])`,
   `("checklist", [...])`, `("steps", [(заголовок, текст), …])`,
   `("table", {"caption":…, "head":[…], "rows":[[…]]})`, `("q", …)` — врезка,
   `("note", …)` — жёлтый блок. Внутри текста работают `{{HOME}}` (главная нужного
   языка) и `{{BLOG}}` (лента), а ссылки на другие статьи пишутся как
   `<a href="../slug/">…</a>` — они одинаково верны в обеих языковых версиях.
4. Сделай обложку `img/blog/<slug>-cover.png` 1200×630 (или попроси меня).
5. `python3 build_blog.py && python3 build_sitemap.py`.

Время чтения считается автоматически (200 слов/мин для EN, 180 для RU), сборка
подсвечивает статьи, выпадающие из диапазона 7–15 минут.

## 5. Аналитика на Supabase

Собирает: просмотры, клики по каждой ссылке и кнопке, переходы наружу
(Telegram/LinkedIn/почта), глубину прокрутки 25/50/75/100 %, время внимания по
секциям, активное время на странице, переключения языка и шаги конструктора
проекта. Без cookie, без персональных данных, без сторонних скриптов.

### 5.1 Настройка (10 минут)

1. **Создай проект** на [supabase.com](https://supabase.com) (free tier).
2. **SQL Editor → New query** → вставь целиком `supabase/schema.sql` → **Run**.
   Создадутся таблица `events`, политики доступа, индексы, 10 представлений
   для отчётов и функция очистки.
3. **Settings → API** → скопируй `Project URL` и `anon public` ключ.
4. Вставь их в двух местах:
   - `js/analytics.js` — вверху, объект `CONFIG`;
   - `admin/index.html` — вверху `<script>`, переменные `SUPABASE_URL` / `SUPABASE_ANON_KEY`.
5. **Authentication → Users → Add user** → создай себе пользователя с паролем.
   Это логин в админку. (В *Authentication → Providers* отключи «Enable email
   signups», чтобы регистрироваться мог только ты.)
6. Задеплой, зайди на сайт, потом открой `/admin/` и войди.

Публиковать `anon` ключ безопасно: политики RLS из `schema.sql` разрешают ему
**только вставку**. Чтение доступно лишь авторизованному пользователю.

### 5.2 Где смотреть данные

**Вариант А — своя админка `/admin/`.** Вход по паролю, фильтр по периоду и
языку, тёмная тема. Показывает: посетителей, сессии, просмотры, среднее время,
процент отказов, клики в Telegram; графики трафика, самых читаемых страниц,
источников и глубины прокрутки; таблицы по страницам, кликам, движению
«откуда → куда», страницам выхода, вниманию по секциям, воронке конструктора и
последним сессиям.

**Вариант Б — дашборд самого Supabase.** В `schema.sql` уже готовы представления,
их можно смотреть в Table Editor или собрать графики в **Reports → New report →
SQL block**. Готовые запросы — в конце файла `schema.sql`:

```sql
select * from v_daily where day > current_date - 30 order by day;   -- трафик
select * from v_pages where page_type='article' order by pageviews desc;
select * from v_clicks limit 30;                                     -- по чему кликают
select * from v_scroll where path like '/blog/%';                    -- где бросают читать
select * from v_flow order by transitions desc limit 40;             -- путь по сайту
select * from v_sections where path='/' order by total_seconds desc; -- внимание по секциям
```

### 5.3 Лимиты и обслуживание

- Free tier: 500 МБ базы, 5 ГБ трафика, до 2 проектов. Одно событие ≈ 300 байт,
  то есть ~1,5 млн событий помещаются в лимит.
- **Проект на бесплатном тарифе засыпает после недели без обращений.** Живой
  трафик его будит; если сайт стоит без посетителей — просто зайди в консоль.
- Чистка старых событий: `select public.prune_events(180);` (оставит 180 дней).
  Если в проекте включён `pg_cron`, можно поставить на расписание:
  `select cron.schedule('prune-events','0 3 * * *','select public.prune_events(180)');`
- Проверить, что всё работает: поставь `debug: true` в `js/analytics.js` — события
  будут печататься в консоль браузера вместо отправки.

### 5.4 Свои события

```js
window.ganzaTrack("cta", "название-кнопки");
```

Уже размечены ключевые элементы через `data-track` (логотип, переключатель языка,
кнопки Telegram, CTA в статьях, карточки блога, «по теме», навигация между
статьями) и все шаги конструктора проекта.

## 6. Деплой на GitHub Pages

1. Залей содержимое папки в репозиторий (`index.html` — в корне).
2. **Settings → Pages → Deploy from a branch**, ветка `main`, папка `/ (root)`.
3. Через 1–2 минуты сайт доступен по адресу репозитория.
4. Добавь сайт в [Google Search Console](https://search.google.com/search-console)
   и [Яндекс.Вебмастер](https://webmaster.yandex.ru/), отправь `sitemap.xml` в обоих.
   Код подтверждения — мета-тег в `<head>`: добавь его в `build_head()` в
   `buildlib.py` (параметр `extra_meta`), чтобы он попал на все страницы сразу.
5. Свой домен: файл `CNAME` в корне + A/CNAME-записи у регистратора, затем
   поменяй `SITE` в `buildlib.py` и пересобери.

Файл `.nojekyll` уже создаётся сборкой — без него GitHub Pages пропускал бы
папки, начинающиеся с подчёркивания.

## 7. Конструктор проекта и цены

Логика расчёта не менялась — она в `js/builder.js`, константы `TYPE_CONFIG` /
`RISK_CONFIG` в начале файла:

```
personDays          = масштаб × базовые_дни[тип] × готовность × координация
personDaysWithRisk  = personDays × (1 + буфер_риска)
эффективность       = clamp(1 − 0.035 × (команда − 1), 0.60, 1)
календарные_дни     = personDaysWithRisk / (команда × эффективность)
бюджет              = personDaysWithRisk × ставка[тип]
```

Добавлено только одно: каждый шаг визарда и показ результата отправляют событие
`builder`, поэтому в админке видно, на каком вопросе люди бросают.

Тарифы (`$450` точечная экспертиза, `$1 100` быстрое внедрение, `от $2 500`
флагман, `от $1 400/мес` резерв) продублированы в `OFFERS` в `build_site.py` —
они попадают в JSON-LD `OfferCatalog`. Меняешь цену на сайте — поправь и там.
